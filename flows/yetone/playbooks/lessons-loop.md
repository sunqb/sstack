# 错题本循环（本 flow 的核心）

对照 Magpie 仓库里实际在用的机制，而不是自创一种日记体。

## 写

1. 复盘一批已合并的提交（建议按自然日或按发布）。只问：是否又修了一遍、是否不该合、验证是否太薄。
2. 新教训写成：加粗规则 + 原因 + 证据 + `Seen 1× (日期)`。
3. 若是已有规则再次出现：在 `Seen` 里加上**新的日期**，并把新证据附在该条下面。同一天发现多次不加计数。
4. 可选写下 Done right：后来做对的提交，帮助以后的 agent 模仿。

## 读

- 任何改代码的会话开始时阅读 `LESSONS.md`（`AGENTS.md` 与 `CLAUDE.md` 已经如此要求）。
- 审查 PR 时同时对照已升格的 `docs/code-standards.md`。

## 升格

- `Seen` 达到 3 个或更多个**不同日期**后，把规则搬进 `docs/code-standards.md`。
- 在 `LESSONS.md` 文末「Moved to the code standards」留下索引和那些日期。
- 升格后，审查以 code-standards 为准；不要让两份文件各写一套互相漂移的正文。

不要把错题本写成随笔，也不要改用 poteto 的 `corrections.md` 代替这一循环。本 flow 允许、并且要求，教训先以带证据的规则存在；反复出现后再变成硬标准。若你同时能把某条规则写成 lint 或测试，欢迎立刻补上——这是加强，不是改用另一套方法论。
