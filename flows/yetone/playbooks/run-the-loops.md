# 如何跑并行 loop

只有在你确实需要持续盯 issue、反馈或自动合并时才启用。许多个人项目只需要错题本循环，不必三条 loop 全开。

1. 把 `loops/01-inbox.md`、`02-feedback.md`、`03-lessons.md` 里的提示词改成你的仓库、渠道和发布方式。
2. 用你选择的 agent 周期执行（yetone 公开分享时用的是 Claude Code 的 `/loop`）。间隔自己定；不要把「未写间隔」理解成作者规定了默认值。
3. 三条 loop 分开跑，不要做一个万能会话同时盯所有入口。
4. 对外回复、合并、发版之前，确认已经在真实环境里验证；高风险操作可以先加人工闸门（这是后继实践者的常见改动，不是 yetone 原帖的强制要求）。
5. 第 2 条 loop 务必先做廉价过滤，再调用贵模型。
6. 第 3 条 loop 必须能改 `LESSONS.md`，并在达到门槛时改 `docs/code-standards.md`。
7. 人定期看 UI/UX 和设计拍板。已经写进 `docs/design.md` 的决定，不要让 loop 擅自推翻。

权限：给 agent 的写仓库、回 issue、发版权限能有多小就多小。屏蔽贡献者必须经维护者。
