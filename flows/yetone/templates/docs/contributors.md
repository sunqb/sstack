# 社区贡献

若项目接受外部 PR，用这套闸门保护仓库。精神来自 yetone/magpie 的 `docs/contributors.md`：先查危害，再谈内容；屏蔽由**维护者**决定，agent 只提议。

## 先查危害

出现任一情况，停止审查，等维护者查看（并写明是哪一行触发的）：

- 改动 CI、发布脚本、工作流权限、密钥或部署描述
- 新增网络地址、上传、遥测，或把凭据、cookie、本地文件发到新的地方
- 在目标并不需要时读写凭据、钥匙串或 agent 配置
- 新增依赖、安装脚本、二进制、压缩/编码后的大段载荷，或运行时从字符串拼出代码
- 把已被维护者否决的第三方通道、广告或推广加回来

在装有真实账号的环境里跑 PR 代码之前，必须先通过这一段。

## 可以不审就关

用一两句话说明理由后关闭：

- 推翻 [design.md](design.md) 或 code-standards 里已拍板的决定，且没有新的论据
- 因同一理由被关过后原样再开
- 短时间内大量几乎相同的 PR

## 提议屏蔽作者

出现以下任一情况，agent 可以向维护者**提议**屏蔽，并附上 PR 编号、日期和问题描述。agent 不得自行执行屏蔽。

1. 至少 3 个 PR 被维护者视为低价值（错误、未测、无关、机器灌水），且合并率低于 30%
2. 在被明确拒绝后，两次以同一内容再开
3. 欺骗：把目标之外的改动藏起来、伪造测试或验证
4. 短时间机器式连开低价值 PR
5. 被告知不可后再加回已移除的依赖、通道或广告

维护者决定后，被屏蔽作者的新 PR 与 issue 关闭即可，不必继续争论。
