# Loop 1：代码协作与社区入口

把项目名、issue 来源和社区渠道换成你自己的。结构来自 yetone 公开的第一条 `/loop`（主帖截图的转写，见 `flows/yetone/README.md` 来源节），已去掉具体产品与话术。

将下面这段交给会周期执行的 agent（例如 Claude Code 的 `/loop`）。按你的工具补上间隔；作者原截图未写间隔。

```
盯一下本仓库的 issue，仔细分析哪些值得修复或实现。做完后发版（若你有发布权）并回复提问的人；不值得做的也要回复，说明原因。对已经由维护者定调拒绝的请求，使用 docs/design.md 里的既定说法，不要把被否决的方向重新做进去。

同时盯仓库的 PR：认真看每一行和每一处逻辑，把代码拉到本地实际跑一遍，验证没有问题。只有在审查过并且实际运行也没有问题之后才能合并；否则回复或关闭，并写明缺了哪一步验证。不要合并明显未经测试、只由编程 agent 堆出来的改动。

如果项目有用户社区（聊天室、论坛、讨论区），查看所有相关频道，不要漏掉。有价值的反馈就去修复或增加功能；值得继续讨论的就继续讨论。回复时使用能真正通知到对方的提及方式，不要只写一个不会产生通知的名字。
```
