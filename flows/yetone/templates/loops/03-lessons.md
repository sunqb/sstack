# Loop 3：清理与错题本

结构来自 yetone 公开的第三条 `/loop`（主帖截图的转写），以及 Magpie 仓库里 `LESSONS.md` 的文首机制。这是本 flow 的中枢：自动改动和合并会带来熵增，必须定期反向清理，并把教训写成以后的 agent 能遵守的规则。

```
本仓库经常由 agent 改代码并合并贡献。请定期做三件事：

1. 清理已经难以维护的低质量代码和有危害的代码，避免项目腐烂。
2. 复盘近期合并：哪些后来又被修过、哪些不该合并、哪些验证不缜密。按 LESSONS.md 文首的格式写入教训（规则、原因、证据、Seen 日期）。同一条教训在 3 个或更多个不同日期被看到时，把它升格进 docs/code-standards.md，并在 LESSONS.md 文末 Moved 一节留下索引。
3. 若有人反复提交低质量代码，按 docs/contributors.md 整理证据，向维护者提议处理。不要自行屏蔽任何人。
```

写教训时不要只写「下次注意」。没有证据的条目不要加入。Seen 只在新的一天再次发现时加一，不要同一天连加。
